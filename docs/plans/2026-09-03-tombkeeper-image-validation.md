## 目标

解决 [issue](../issues/2026-09-03-tombkeeper-image-validation.md)，阻止非图片内容进入 OSS，并修复
生产库中 `cdn.ipfsscan.io` 来源的存量坏图。

## 关键决策与方案

### 下载内容校验

- 在 `GetPicStream` 返回候选成功之前，使用 Go 标准库 `http.DetectContentType`
  识别前 512 字节中的 JPEG、PNG、GIF、WebP；
  不信任 HTTP Content-Type 或扩展名。拒绝 HTML、JSON、空流和无法识别的内容，包括长度未知的空流。
- 复用同一校验函数检查 OSS 文件；返回的读取流必须回放已读取的前缀，保留 Close 与取消语义，
  下载响应 Content-Type 使用识别结果，避免合法图片被错误响应头赋予错误扩展名。
- 本次验证内容类型与基本文件头，不承诺检查整张图的每个像素或检测所有尾部损坏。
- 从候选列表移除已返回欢迎页的 IPFS 代理；不扩大主机白名单。有效新浪及其他代理仍参与选择。

### 自动迁移 `20260903000000`

- 新增注册项 `tombkeeper-ipfsscan-image-repair`，不修改已经发布的 migration。使用当前资产表，
  无需等待无关历史迁移；沿用框架的失败告警、仅成功后记账和下次重试机制。
- 按 ID 分批读取未软删除图片记录，以解析后的 URL 主机精确判断 `cdn.ipfsscan.io`，同时覆盖 HTTP、
  HTTPS 和已有失败状态。不得仅按 status=0 限定范围，也不得误包含相似域名。
- 根据记录的存储位置读取 OSS 文件。有效图片且状态正常时不改写。对象键为空、对象不存在或内容不是
  图片时进入修复；网络、鉴权和其他存储读取异常单独计失败，避免当成确认损坏而覆盖数据。
- `GetStream` 可能惰性返回对象，缺失、鉴权及网络错误也可能在实际读取前缀时出现；打开和读取两阶段
  使用同样的错误分类。空或未知 storage_provider 的已有对象不能猜测当前 bucket，计为可重试失败；
  无对象键的失败记录可以直接重下。当前生产目标资产的 provider 均为 `https://oss.darkeli.com/rss`。
- 每个存储读取设置有界超时并关闭流；不能仅在外层等待 goroutine 超时而遗留挂起读取。
- 重新使用图片 ID 从剩余候选源下载，下载入口执行同样的内容校验。写入
  `tombkeeper/repair-20260903/<pic_id>.<实际格式>`，不覆盖旧文件，保证备份数据库可恢复旧引用。
  新路径也避免浏览器继续命中旧坏图缓存。
- 文件上传成功后，更新该资产的 object_key、url、storage_provider、status 和 updated_at；绕过
  `SaveImageAsset` 对已有成功记录的保护逻辑，以条件更新防止静默覆盖并发修改。数据库更新失败计为失败。
  `RowsAffected == 0` 视为并发冲突，不能计为修复成功。
- 新文件上传与数据库更新不能组成事务。使用确定的新路径，使上传成功、数据库更新失败或进程退出后，
  旧记录仍指向原文件；下次扫描会继续修复，不因原文件已被覆盖为有效图片而漏改真实来源。
- 已是有效文件但状态失败的记录只纠正状态；真实来源不臆造。单条失败继续处理，定期输出扫描、正常、
  修复及失败数量，最终有任何失败就返回错误，不写完成记录。无目标记录时无需初始化网络服务。

### 发布与生产验证

- 定向验证 `pkg/routers/tombkeeper`、`internal/migrate`、受影响的 archive 测试，执行 `just lint`；
  预存基线失败单列，不混入无关修复。
- 独立实现评审后更新 PROGRESS，squash 合并 master 并删除工作分支。
- 使用 `rss-zero-release` 按本月本地及远端 tags 计算版本，经 `just build-docker --tag <tag> --push`
  发布镜像；推送代码与 tag。发布时确认实际可用远端，不改动已发布 tag。
- 部署前在生产机做 PostgreSQL 自定义格式备份，检查备份目录可读并记录恢复方法；保留旧对象。
- 更新 SERVER_TAG，拉取并启动后观察自动迁移，确认版本、健康、完成记录与统计；示例三张坏图必须
  改为真实图片且存档使用新 URL。检查所有剩余该 CDN 来源记录应为有效文件；未修复项必须明确报告。
- `RunAuto` 同步发生在 HTTP 监听之前，部署期间需等待迁移进度，不能因短时间健康请求失败而重启。
  保持逐批进度可见；出现不可恢复错误时按备份与旧版本恢复流程处理，不擅自标记迁移成功。
